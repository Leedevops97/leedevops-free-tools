# Server Lens Web 用户说明书

适用版本：1.1.0 · 更新日期：2026-10-22

Server Lens Web 是免费的开源 Linux 服务器监控工具。它通过 Node Exporter
读取系统指标，由 Prometheus 保存，再用浏览器仪表盘展示。安装在需要监控的
Linux 服务器上；查看时，在自己的电脑上打开浏览器即可。

## 1. 先分清三个入口

| 入口 | 用途 | 访问方式 |
|---|---|---|
| Server Lens Web 仪表盘 | 日常查看 CPU、内存、根磁盘和运行时长 | 建立 SSH 隧道后打开 http://127.0.0.1:18790/ |
| Prometheus 原生网页 | 手动查询指标、检查采集情况 | 另外转发 19090 端口后打开 http://127.0.0.1:19090/ |
| 官网交互演示 | 安装前体验界面 | 从[官网产品页](https://www.leeimages.com/server-lens-web/)点击演示 |

日常使用第一个入口即可。官网演示明确标注模拟数据，不代表你的服务器状态。
独立仪表盘提供英文和简体中文；官网产品页另有其他语言。

`127.0.0.1` 表示当前使用的设备。SSH 隧道需要在**打开浏览器的那台电脑上**建立，
不能只在远程服务器终端里运行转发命令。手机、另一台电脑不会自动共享这个隧道。

## 2. 服务器已经安装：怎样打开面板

在自己的电脑上打开终端。Windows 可以使用 PowerShell。将下面的用户名和服务器
地址换成自己的 SSH 登录信息：

```sh
ssh -N -L 127.0.0.1:18790:127.0.0.1:18790 YOUR_USER@YOUR_SERVER
```

使用指定私钥时，增加 `-i` 参数，例如：

```powershell
ssh -i "C:\path\server.pem" -N -L 127.0.0.1:18790:127.0.0.1:18790 YOUR_USER@YOUR_SERVER
```

登录成功后，终端没有命令提示符、保持等待是正常现象。保持窗口开启，在同一台电脑
的浏览器输入 **http://127.0.0.1:18790/**。首次连接 SSH 时，应核对服务器指纹。

关闭隧道可按 `Ctrl+C`。这只会断开这台电脑的访问，服务器仍继续采集。
服务器重启后，已启用的三个服务会自动启动；电脑重启后，需要重新建立 SSH 隧道。

该面板没有单独的账号密码，访问权限来自 SSH。三个监控服务都只监听服务器本机，
无需在云安全组开放 18790、19090 或 19100 端口。

### 本地端口被占用

如果已有有效隧道，直接打开原地址即可。如果本地 18790 被其他程序占用，可改用
本地 18791，服务器端口保持 18790：

```sh
ssh -N -L 127.0.0.1:18791:127.0.0.1:18790 YOUR_USER@YOUR_SERVER
```

随后访问 http://127.0.0.1:18791/。不需要修改服务器配置。

## 3. 第一次安装到自己的服务器

已有部署的服务器跳过本节。

需要 Linux、systemd、Python 3.9 或更高版本，以及 sudo/root 权限。
安装程序提供 x86_64 和 aarch64 二进制校验值；已实际验证 Ubuntu 26.04 / x86_64，
ARM64 和 RHEL 系列仍需自行验证。适合物理机或虚拟机，不用于显示容器自身的资源限额。

1. 从[GitHub 发布页](https://github.com/Leedevops97/leedevops-free-tools/releases/tag/server-lens-web-v1.1.0)
   获取 ZIP 和对应的 `.sha256` 文件。
2. 将文件放在服务器同一目录，用 `sha256sum -c server-lens-web-1.1.0.sha256`
   核对完整性，再解压 ZIP。
3. 阅读 README 和安装程序，在包含 `tools` 目录的位置运行：

```sh
sudo python3 tools/server-lens-web/install.py
```

安装程序会从 GitHub 下载固定版本的官方 Prometheus 和 Node Exporter，核对校验值，
创建三个 systemd 服务并设置开机自启。源码 ZIP 不包含这些二进制；第一次安装仍需
下载约 124MB 的官方压缩包，实际以安装程序锁定的架构为准。已下载的文件会缓存。

安装完成后，按第 2 节在自己的电脑上建立隧道。重复运行安装程序不会升级或重写已有
托管安装；发现不属于本工具的冲突文件时会停止。

## 4. 看懂面板上的数字

| 项目 | 含义 |
|---|---|
| CPU 使用率 | 所有逻辑核心的平均忙碌比例，以最近两分钟的 idle 计数变化计算；不是瞬时值 |
| 内存 | 使用系统的 MemAvailable 估算可用内存，区别于单看完全空闲内存 |
| 根磁盘 | 只统计 `/` 文件系统，不是所有磁盘总和；应用不可用的保留空间计入占用 |
| 运行时长 | 从最近一次系统启动到现在的时间，重启后重新计算 |
| 资源趋势 | 已采集到的 CPU、内存或根磁盘历史百分比 |

容量使用 GiB 等二进制单位。磁盘占用口径可能与 `df` 的百分比不同，这是保留空间
计算方式不同；查看“应用可用磁盘空间”可以了解程序实际还可使用多少空间。

显示“正常上报”表示采集和查询工作正常，不等于服务器没有任何故障。
本版不提供登录记录、进程分析、时间同步状态、告警通知或自动修复；原终端版
Server Lens 的检查范围与网页版不同。

## 5. 日常交互

- **语言**：右上角选择 EN 或中文。浏览器会在本机保存语言偏好。
- **切换图表**：点击 CPU、内存、根磁盘按钮，卡片仍同时展示四项基础信息。
- **时间范围**：选择 1h、6h 或 24h。只显示安装后实际采集到的历史，不补造旧数据。
- **暂停 / 继续**：暂停浏览器自动刷新，保留最后一次数据及时间；服务器继续采集。
- **刷新**：手动请求一次数据；后端有 25 秒缓存，不保证每次点击数值都会变化。

采集间隔为 30 秒；页面可见且未暂停时，每 30 秒刷新。切到后台时减少自动请求。
历史配置保留 48 小时，但本版界面最多查看最近 24 小时。

初次启动 CPU 需要至少两次采样，通常等待约一分钟；其他指标可能先出现。
缺失或过期指标显示未知 / 不可用，不会伪装成 0%，也不会切换到模拟数据。

## 6. 怎样打开 Prometheus 原生网页

如需直接查询指标，在自己的电脑另开终端建立第二条隧道：

```sh
ssh -N -L 127.0.0.1:19090:127.0.0.1:19090 YOUR_USER@YOUR_SERVER
```

在浏览器打开 http://127.0.0.1:19090/。可在查询界面输入下面的表达式并执行：

```promql
up{job="server_lens"}
```

结果 `1` 表示最近一次抓取成功，`0` 表示失败；没有结果表示还没有对应序列或配置
需要检查。原生 Prometheus 侧重指标查询，日常的四卡片界面在 18790。

## 7. 常见问题

| 现象 | 先检查什么 |
|---|---|
| 浏览器提示连接被拒绝 | 本机 SSH 隧道窗口是否还开着；端口是否和地址一致 |
| SSH 登录失败 | 用户名、私钥路径、服务器地址以及 SSH 端口；确认普通 SSH 登录可用 |
| 页面能开，数值显示不可用 | 检查下方三个服务状态，查看采集器及 Prometheus 日志 |
| 刚安装时 CPU 没数字 | 等待至少两次采样，再刷新；仍无数据时检查服务 |
| 选择 24h，但只有一小段历史 | 安装时间不足 24 小时，或期间服务曾停止 |
| 看到“模拟数据”横幅 | 打开的是演示页，应改用本机隧道地址查看真实监控 |
| 重启电脑后打不开 | 重新建立 SSH 隧道；这不一定是服务器故障 |
| 内存或磁盘数字与其他工具不同 | 先对照第 4 节的统计口径 |

下面的检查命令在 **Linux 服务器 SSH 终端**执行，不是在本地 PowerShell 执行：

```sh
sudo systemctl status leedevops-prometheus leedevops-node-exporter leedevops-server-lens-web --no-pager
sudo journalctl -u leedevops-prometheus -u leedevops-node-exporter -u leedevops-server-lens-web --since '10 minutes ago' --no-pager
```

日志用于判断原因，不要因为数字暂时缺失就反复重装。需要帮助时，可联系
**lx.iwtfree@gmail.com**，说明版本、系统、页面状态和已脱敏的报错。

## 8. 管理与资源

| 内容 | 默认位置 |
|---|---|
| 工具、界面和配置 | `/opt/leedevops/server-lens-web/` |
| Prometheus 历史数据 | `/var/lib/leedevops-prometheus` |
| 服务定义 | `/etc/systemd/system/leedevops-*.service` |

Prometheus 的历史块保留目标为 128MB；WAL、内存数据和压缩需要额外磁盘空间，
这不是整个目录的硬上限。应保留至少 1GB 可用空间。服务内存上限分别为
Prometheus 256MiB、Node Exporter 64MiB、网页服务 64MiB；上限不是实际占用承诺。

停止监控并取消开机自启，保留代码、配置和数据：

```sh
sudo systemctl disable --now leedevops-server-lens-web leedevops-prometheus leedevops-node-exporter
```

恢复监控及开机自启：

```sh
sudo systemctl enable --now leedevops-node-exporter leedevops-prometheus leedevops-server-lens-web
```

真实监控数据保存在安装服务器上，不上传到 Leedevops。服务没有多用户隔离功能，
应供可信 SSH 用户访问。升级前保留配置和所需数据；1.1.0 安装程序不执行原地升级
或自动卸载。项目代码使用 MIT 许可，上游组件保留 Apache-2.0 许可。
